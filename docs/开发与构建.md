# 开发与构建

普通使用者打开工具网址或下载使用包。以下步骤用于维护源码和重新生成下载包。

## 环境

需要 Node.js 22 或以上版本及自带的 npm。首次安装依赖需要联网；生成的离线网页不需要联网。

Windows PowerShell 中可用 `.cmd` 入口执行 npm，无需为了运行 npm 而调整 PowerShell 的脚本执行策略。

```powershell
node --version
npm.cmd --version
```

## 从源码生成发行包

在直接包含 `package.json` 的项目根目录，先安装锁定的依赖：

```powershell
npm.cmd ci
```

完成后执行：

```powershell
npm.cmd run release
```

此命令会依次进行类型检查、测试、构建与打包。输出包括：

| 路径 | 内容 |
|---|---|
| `dist/index.html` | 单文件离线网页 |
| `release/ime-dictionary-exporter-offline-1.2.0.zip` | 普通使用者下载包 |
| `release/ime-dictionary-exporter-source-1.2.0.zip` | 源码下载包 |
| `release/ime-dictionary-exporter-pages-1.2.0.zip` | 可部署的静态网站文件 |
| `release/SHA256SUMS.txt` | 三份 ZIP 的 SHA-256 校验和 |

版本号变化后，ZIP 名称会随 `package.json` 中的版本变化。

## 日常修改

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
```

分别用于类型检查、导出与存储测试、重新生成网页。构建后，用浏览器重新打开或刷新 `dist/index.html`。

修改文档后，如果应用代码没有变化且已有通过检查的构建结果，可以只重新打包：

```powershell
node scripts/package.mjs
```

程序变更后应重新构建；不要用旧 HTML 搭配新源码发布。

## 更新版本

例如把 `1.2.0` 更新为 `1.2.1`：

```powershell
npm.cmd version patch --no-git-tag-version
npm.cmd run release
```

命令会更新项目版本及锁文件；随后提交代码、推送 GitHub，再为新版本创建发行版。README 或说明中如果写有具体旧文件名，也应一并更新。

## 结构

- `src/App.tsx`：编辑界面。
- `src/components/ProfileList.tsx`：方案拖动排序、键盘排序和删除入口。
- `src/lib/storage.ts`：本地保存、并发检查、网站路径隔离与临时会话。
- `src/lib/export.ts`：六种输入法文件及 ZIP 导出。
- `src/lib/lexicon.ts`：数据校验。
- `src/lib/presets.json`：七个预置词库方案。
- `scripts/`：构建、测试和打包脚本。
- `tests/`：微软二进制对照、导出及本地存储测试。
- `.github/workflows/build.yml`：可在 GitHub Actions 中手动运行的构建工作流。

`build.yml` 的构建产物可以下载，但不会自动创建 Release。另有 `pages.yml`，在推送 `main` 或手动运行时验证、构建并发布 `dist` 到 GitHub Pages。设置方法见 [GitHubPages发布教程](GitHubPages发布教程.md)。

网页与本地 HTML 使用同一套源码和构建结果，不需要另建项目或后端。网站数据库按所在目录隔离；本地文件沿用原数据库名，以保留已有保存数据。

项目英文名为 **Multi-platform IME Custom Dictionary Exporter**，包名和发行文件前缀为 `ime-dictionary-exporter`。浏览器内部保留旧的存储标识，以兼容已有数据；它们不影响项目对外名称。

使用指南直接读取 `docs/使用说明.md`、`docs/词库数量说明.md` 和 `docs/词库来源.md`，在构建时嵌入网页。程序及第三方许可全文也写入 HTML，因此 offline 包只需一个 HTML 文件。
